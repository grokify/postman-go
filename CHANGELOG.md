## [v0.2.0] - 2026-10-27 ([`20f95eb`](https://github.com/grokify/postman-go/commit/20f95eb))

### Highlights

- New `ocsf` package maps Secret Scanner findings to OCSF Detection Finding events (`class_uid` 2004) for SIEMs and data lakes, with optional enrichment for resource names, owners, and remediation guidance
- Fixes for live API responses the TypeScript-derived spec got wrong: fractional metered operation values, `null` Secret Scanner cursor and resolution fields, and the Secret Scanner's string-typed default `limit` echo
- New guides for OCSF export and testing, plus opt-in integration tests against the live API

### Breaking

- `users.Operation` `Usage`, `Limit`, and `Overage` change from `int` to `float64`, because some metered operations (for example `test_data_storage`) report fractional values ([`10c62ec`](https://github.com/grokify/postman-go/commit/10c62ec))

### Upgrade Guide

- Code that reads `users.Operation` `Usage`, `Limit`, or `Overage` as `int` must switch to `float64`, or convert explicitly with `int(op.Limit)` ([`10c62ec`](https://github.com/grokify/postman-go/commit/10c62ec))
- The module now requires Go 1.26 or later (up from 1.25), following the OpenTelemetry v1.47.0 upgrade ([`8c64226`](https://github.com/grokify/postman-go/commit/8c64226))

### Added

- `ocsf` package: `FromQueryResult`, `FromDetectedSecret`, `FromDetectedSecretWithLocations`, `FromDetectedSecretEnriched`, `FromActivityFeed`, and `FromActivityFeedEntry` map Secret Scanner results to OCSF Detection Findings, with `Options` for product name and schema version and `Enrichment` for caller-resolved owners, resource names, and per-type remediation ([`d055c9f`](https://github.com/grokify/postman-go/commit/d055c9f))
- Spec generator per-field overrides: `FLOAT_FIELDS` types listed fields as `number`/`double` and `NULLABLE_FIELDS` marks listed fields nullable, so live-API corrections survive regeneration ([`65dd73d`](https://github.com/grokify/postman-go/commit/65dd73d))

### Changed

- Secret Scanner `Query` and `Locations` now send `limit=100` (the API's maximum page size) when the caller leaves `Limit` at `0`, instead of omitting the parameter ([`883fb73`](https://github.com/grokify/postman-go/commit/883fb73))
- Minimum Go version raised from 1.25 to 1.26 ([`8c64226`](https://github.com/grokify/postman-go/commit/8c64226))

### Fixed

- Secret Scanner `Query` and `Locations` failed to decode when no limit was given, because Postman echoes its implicit default page size back as a string (`"limit":"30"`) ([`883fb73`](https://github.com/grokify/postman-go/commit/883fb73))
- Secret Scanner `Locations` failed to decode an unresolved secret's response, because the live API returns `null` for `meta.cursor` and for the activity-feed `resolvedAt` and `resolvedBy` ([`65dd73d`](https://github.com/grokify/postman-go/commit/65dd73d))
- `Users().Me` failed to decode when a metered operation reported a fractional value (for example a `test_data_storage` limit of `8.88`) ([`10c62ec`](https://github.com/grokify/postman-go/commit/10c62ec))

### Dependencies

- _5 dependency updates_

### Documentation

- Guides for exporting findings to OCSF and for running unit and integration tests; `ocsf` listed on the home page ([`8db879a`](https://github.com/grokify/postman-go/commit/8db879a))
- Service pages document the Secret Scanner default limit, pagination, and `null` activity-feed fields, and `float64` operation values; installation page lists Go 1.26; generator README documents the per-field overrides ([`cd3062d`](https://github.com/grokify/postman-go/commit/cd3062d))
- README covers OCSF export, testing, the generator overrides, and the Go 1.26 requirement ([`20f95eb`](https://github.com/grokify/postman-go/commit/20f95eb))

### Tests

- Decode regression tests replaying live API response shapes: the default page limit, `null` Secret Scanner cursor and resolution fields, and fractional operation values ([`bc28e89`](https://github.com/grokify/postman-go/commit/bc28e89))
- `ocsf` mapping, enrichment, and OCSF schema validation tests ([`aee3ff2`](https://github.com/grokify/postman-go/commit/aee3ff2))
- Opt-in integration tests for `/me`, workspaces, collections, and teams against the live API, skipped unless `POSTMAN_API_KEY` is set ([`dae1448`](https://github.com/grokify/postman-go/commit/dae1448))

## [v0.1.0] - 2026-08-10 ([`0c37559`](https://github.com/grokify/postman-go/commit/0c37559))

### Highlights

- Initial release: a Go SDK for the Postman API covering all 31 service areas (196 endpoints) through a single `*postman.Client`
- Postman publishes no downloadable OpenAPI document, so `scripts/gen-openapi` reconstructs one from Postman's official TypeScript SDK via a reusable ts-morph generator, keeping the grokify SDK pipeline consistent across providers
- Full MkDocs documentation site (installation, auth, errors, rate limiting, and a usage page per service) plus a Scalar-rendered API reference generated from the OpenAPI spec

### Added

- TypeScript-SDK-to-OpenAPI spec generator (`scripts/gen-openapi`) and the reconstructed OpenAPI 3.0.3 spec (`openapi/openapi.yaml`) covering all 31 service areas / 196 endpoints ([`bcdad64`](https://github.com/grokify/postman-go/commit/bcdad64))
- ogen-generated internal API client (`internal/api`) covering all 196 endpoints, generated via ogen v1.24.0 ([`0cdcd0d`](https://github.com/grokify/postman-go/commit/0cdcd0d))
- Shared `postmanerr` package: `APIError`, `FromProblemDetails` (RFC 9457 problem-details mapping), and `Empty` (for TS union error schemas that collapse to no recoverable body detail) ([`48e99e4`](https://github.com/grokify/postman-go/commit/48e99e4))
- Secret Scanner service wrapper (`secretscanner`) — the first hand-written service package, establishing the pattern (plain Go input/result types, string-const enums, `postmanerr`-based error mapping) every other service follows ([`97e1736`](https://github.com/grokify/postman-go/commit/97e1736))
- Collections, Specs, and Workspaces service wrappers ([`eed1b4d`](https://github.com/grokify/postman-go/commit/eed1b4d))
- Mocks, Collection Items, Teams, and SDK Generation service wrappers ([`8f96d0a`](https://github.com/grokify/postman-go/commit/8f96d0a))
- Environments, Components, Monitors, Private API Network, and Tags service wrappers ([`98c04a4`](https://github.com/grokify/postman-go/commit/98c04a4))
- Collection comment (folders/requests/responses) and Users service wrappers ([`21c0282`](https://github.com/grokify/postman-go/commit/21c0282))
- Pull Requests, OAuth 2.0, Groups, and Collection Access Keys service wrappers ([`ca098f7`](https://github.com/grokify/postman-go/commit/ca098f7))
- Billing, Audit Logs, Analytics, Webhooks, and Service Accounts service wrappers ([`33c8e03`](https://github.com/grokify/postman-go/commit/33c8e03))
- Search, Postbot, Import, Comments, and API Security service wrappers ([`8abe80c`](https://github.com/grokify/postman-go/commit/8abe80c))
- Top-level `postman.Client` wiring all 31 services, with one accessor per service (`Collections()`, `Workspaces()`, `SecretScanner()`, ...), shared auth/HTTP configuration, and `API()`/`BaseURL()` escape hatches ([`343ee9c`](https://github.com/grokify/postman-go/commit/343ee9c))
- Scalar-powered API reference page (`docs/api-reference.html`) rendering `openapi/openapi.yaml` ([`751c09a`](https://github.com/grokify/postman-go/commit/751c09a))

### Fixed

- gosec G101 false positives on `EnvAPIKey`, `SecretTypeOriginTeamRegex`, and `MetricCreditUsageByModel` — the identifier names matched gosec's credential heuristic even though the values are an environment variable name and public enum tags, not secrets ([`76f83b5`](https://github.com/grokify/postman-go/commit/76f83b5))
- dupl false positives on sibling wrapper methods that each switch over a distinct ogen-generated response/error type (`collectionitems`, `sdkgen`, `specs`, `tags`) — no common interface exists to extract a shared helper over without reflection or per-type adapters ([`84799cd`](https://github.com/grokify/postman-go/commit/84799cd))
- `collectionitems.CreateResponseInput`/`UpdateResponseInput` embedded an unexported `responseFields` struct, silently breaking composite-literal construction (`&Input{Field: value}`) — the one construction idiom used everywhere else in the SDK. Found while writing and compiling the collection items documentation examples against the real module ([`d916928`](https://github.com/grokify/postman-go/commit/d916928))
